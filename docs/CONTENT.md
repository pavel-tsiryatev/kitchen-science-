# Как писать статьи справочника

Каждая статья — отдельный файл `content/articles/<id>.md`. Сборка превращает файлы в данные
приложения и **останавливается с понятной ошибкой**, если в файле что-то не так
(не тот раздел, нет источников, неверный номер ответа и т. п.).

## Шаблон

```markdown
---
id: c6                       # = имя файла; буква раздела + номер
section: C                   # A–J, см. src/data/sections.json
# group: soup                 # только для раздела I: подгруппа из src/data/dish-groups.json (soup, sides, meat, eggs, dough, veg)
title: Название статьи
idea: Краткий ответ в 1–2 предложения — показывается в карточке и в начале статьи.
related: [c1, c5]            # id связанных статей (должны существовать)
evidence: high               # high | medium | low | unverified
reviewed: 2026-11-05         # дата сверки источников (обязательна, если evidence ≠ unverified)
# ingredients:               # необязательно; у всех блюд раздела I — есть
#   servings: 4               # на сколько порций рецепт (1–50)
#   title: Гречка             # необязательно: если в статье несколько рецептов
#   items:                    # [название, количество, единица]
#     - [Картофель, [600, 700], г]      # число или диапазон [от, до]
#     - [Масло, 2, ст. л.]              # единицы: г, кг, мл, л, шт, ст. л., ч. л., стакан, зубчик, пучок, банка
#     - [Соль, null, по вкусу]          # null — не пересчитывается; третье поле — пометка
quiz:
  question: Вопрос для самопроверки?
  options:
    - Верный вариант
    - Неверный вариант
    - Ещё неверный
  answer: 0                  # номер верного варианта, считая с 0
  explanation: Почему верный ответ верный.
sources:
  - authors: Tornberg E.
    year: 2005
    title: Effects of heat on meat proteins – Implications on structure and quality of meat products
    published: Meat Science, 70(3), 493–508      # журнал, том(выпуск), страницы
    doi: 10.1016/j.meatsci.2004.11.021
  - authors: McClements D. J.
    year: 2015
    title: "Food Emulsions: Principles, Practices, and Techniques (3rd ed.)"
    published: CRC Press, Boca Raton
    isbn: 978-1-4987-2669-6
  - authors: USDA FSIS
    year: 2021
    title: FSIS Cooking Guideline for Meat and Poultry Products (Revised Appendix A)
    published: U.S. Department of Agriculture, Food Safety and Inspection Service
    note: Пояснение, что именно взято из источника (необязательно).
---

## Что происходит
Абзацы разделяются пустой строкой.

## Почему это происходит
## Что влияет на результат
## Как применить на практике
## Типичные ошибки
## Домашний эксперимент
## Границы применимости        ← необязательный раздел
## Коротко
```

Разделы пишутся именно с такими заголовками; порядок в файле не важен, в приложении он фиксированный.
Если в заголовке есть двоеточие или кавычки, возьмите значение в кавычки: `title: "Майяр: что это"`.

## Правила доказательности

| `evidence` | Когда ставить |
|---|---|
| `high` | Механизм подтверждён независимыми рецензируемыми работами или официальными нормами |
| `medium` | Основное подтверждено, но детали сильно зависят от продукта и условий |
| `low` | Практическое правило, данных мало |
| `unverified` | Источники ещё не сверены (старые статьи) |

Для `high`, `medium` и `low`:

1. Каждый источник — с полями `authors`, `year`, `title` и `doi`, `isbn`, `url` или `published`.
   Минимум один источник — рецензируемая статья с DOI.
2. Источники сверены командой `npm run verify:sources` (Crossref и OpenLibrary): совпадают название,
   год, том и страницы. Нужен доступ в интернет.
3. В тексте — только то, что подтверждают источники. Числа давайте диапазонами с оговоркой
   «примерно», если они зависят от продукта. Спорное выносите в «Границы применимости».
4. Нормы безопасности (температуры, время, охлаждение) — только из официальных документов
   (USDA FSIS, FDA Food Code и т. п.), с указанием документа.

### Осторожно с исследованиями, сделанными ИИ

При переработке первых пяти статей из исследования, подготовленного ИИ, сверка нашла ошибки
в ссылках: DOI вёл на совсем другую статью, была перепутана «часть I» и «часть II» одной работы,
не совпадали год и журнал. Поэтому любой источник из такого текста сначала проверяйте
через `npm run verify:sources`, а утверждения — по самой статье.

## Проверка

```bash
npm run test:unit         # формат всех статей и ссылки между ними
npm run verify:sources    # сверка DOI/ISBN с научными базами (нужен интернет)
npm run dev               # посмотреть статью в приложении
```

## Глоссарий

Термины лежат в `content/glossary.yaml`:

```yaml
- id: maillard                 # латиницей, уникальный
  term: Реакция Майяра         # как пишется в тексте
  aliases: [Майяр]             # другие формы и синонимы (необязательно)
  definition: "Цепочка реакций между аминокислотами и сахарами при нагреве…"
  articles: [b1, c2]           # где термин раскрыт подробнее
```

- В статьях ссылкой автоматически становится **первое упоминание** каждого термина — в любой
  грамматической форме («клейковины», «клейковиной»). Если форма глагола не находится
  («денатурируют» для «Денатурации»), добавьте её в `aliases`.
- Определения пишите простыми словами, 1–3 предложения, и согласуйте с проверенными статьями.
- Тесты проверяют, что id и названия не повторяются, статьи существуют и каждый термин
  встречается хотя бы в одной статье.


## Ингредиенты и список покупок

Блок `ingredients` показывается над текстом статьи: читатель меняет число порций, количества
пересчитываются, а кнопка «В список покупок» добавляет продукты в общий список. Пояснение
в скобках («Мука (в крем)») в списке покупок убирается, и одинаковые продукты складываются.
Количества в шагах рецепта не пересчитываются — пишите их для исходного числа порций.
